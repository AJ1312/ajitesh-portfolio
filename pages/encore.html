DISTRIBUTED CORRECTNESS

Six Engineering Pillars of Encore

PILLAR 01 • CONCURRENCY CONTROL

Guaranteed Double-Booking Prevention

Under sudden flash-sale loads, traditional row locks cause database thread exhaustion. Encore enforces Optimistic Concurrency Control (OCC) with atomic version increments within isolated PostgreSQL transactions. Any stale booking attempt is rejected gracefully at the database tier without locking the entire inventory.

PILLAR 02 • CART INTEGRITY

FairHold™ 15-Minute Temporary TTL

Seats are temporarily locked during the checkout flow using an active 15-minute Time-To-Live (TTL). If a customer abandons their session or payment fails, the lock expires automatically in Upstash Redis, releasing seats back to circulation without administrative intervention.

PILLAR 03 • ASYNCHRONOUS QUEUES

Autonomous FIFO Waitlist Auto-Assignment

When held seats expire, background BullMQ workers execute queries with SELECT ... FOR UPDATE SKIP LOCKED to instantly reallocate seats directly to the next person waiting in line, completely circumventing public scalp bots.

PILLAR 04 • REAL-TIME STATE SYNC

Live Real-Time Seat Availability

Bidirectional Socket.io feeds synchronize seat status changes (AVAILABLE → HELD → BOOKED) across all active browser windows in real time, eliminating client-side polling and preventing stale UI states.

PILLAR 05 • STRICT INTEGRITY

End-to-End Type Safety

The pnpm monorepo incorporates shared data models and Zod schemas across both Next.js frontend and NestJS backend via @encore/shared, eliminating runtime serialization mismatches and guaranteeing contract integrity from form input to database column.

PILLAR 06 • ADVERSARIAL DEFENSE

Production-Hardened Security

Incorporates GPU-resistant Argon2id password hashing, stateless JWT Bearer authorization, NestJS Throttler rate limiting against credential-stuffing, Helmet header sanitization, and 100% parameterized SQL queries via Drizzle ORM.
