The Incident

Security Operations Centers drown in alerts. Analysts face alert fatigue from systems that generate thousands of notifications per hour with no context on why an event was flagged. Meanwhile, high-frequency network telemetry demands processing pipelines that can keep pace without ballooning memory consumption. Sentinel-Stream was built to solve both problems simultaneously.

The Engineering

O(1)-Memory Streaming Architecture

• Strictly bounded to < 50MB RAM during continuous high-frequency ingestion

• Sliding window feature computation without storing raw data

• Online statistics (running mean, variance) replace batch computation

Two-Stage LightGBM Pipeline

• Stage 1: Coarse filter eliminates 65% of benign traffic

• Stage 2: Fine-grained classification on remaining flows

• Combined: 0.992 ROC-AUC on CIC-IDS2017 benchmark

• Gradient boosting optimized for streaming inference

TreeSHAP Explainability

• Real-time attribution vectors for every flagged anomaly

• Analysts see which features drove each alert (e.g., payload entropy, IAT variance)

• Feature importance ranking per-alert, not just global

Async FastAPI + WebSocket Microservice

• Live anomaly alerts streamed to SOC-facing dashboard

• Risk scores updated in real-time

• WebSocket connections for zero-latency alert delivery
